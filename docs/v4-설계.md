# 관리자 페이지 V4 설계

작성 2026-11-19. 근거: `V4/claude-code-handoff`(구현 가이드·시안·참고 이미지), 저장소 코드, 공개 스냅샷(익명 읽기).
운영 DB 직접 조회는 연결 도구 권한이 없어(permission denied) 마이그레이션과 공개 자료로 확인했다.

## 1. 한 줄 요약

`admin-v4/`에 **V3와 코드를 나누지 않는 새 관리 화면**을 만든다. 로그인·업로드·AI 같은 바탕 모듈(`admin/js/`)만 같이 쓴다.
같은 DB를 그대로 쓴다. 다만 "확정한 것만 바로 공개"를 지키기 위해 **작성 중인 내용은 임시 칸에 두고, 확정할 때만 실제 표에 넣고 그 자리에서 공개**한다.

## 2. 독립 구조

```
comsw/
  admin-v4/
    index.html        로그인 화면 + 화면 틀(사이드바·위 막대·본문)
    v4.css            시안 색 토큰(--v4-bg #F5F6F7 …), 반응형 900/670/320px
    js/
      main.mjs        로그인·세션 복구·30분 유휴 로그아웃 (V3 main.mjs와 같은 흐름, 화면만 새로)
      app.mjs         역할별 메뉴, 주소(#/menu/…) 이동, 저장 안 한 내용 확인
      data.mjs        V4가 쓰는 DB 읽기·쓰기 모음(화면은 이것만 부름)
      ui.mjs          패널·탭·4단계 버튼·표·미리보기 같은 작은 부품
      pages/          메뉴마다 한 파일 (아래 9개)
    test/             jsdom 화면 테스트
```

- **같이 쓰는 것(가져다 씀, 고치지 않음)**:
  - `admin/js/firebase.mjs`, `session.mjs`: 쌤톡 Firebase 로그인 → 역할 클레임 → 토큰으로 Supabase 접근
  - `roles.mjs`, `messages.mjs`, `idle-logout.mjs`
  - `services.mjs`(AI 요약·프로필 사진 서버 함수 `comsw-tools`), `image-upload.mjs`(20MB, 자동 줄이기)
- **같이 쓰지 않는 것**: `admin-v3/` 화면 코드 전부, V3 CSS. V4 화면은 V4 파일만으로 그린다.
- 같은 주소(rladiddus.github.io/comsw)라 로그인 상태가 V3와 공유된다. V3는 전환 때까지 그대로 쓸 수 있다.
- 시안의 관리자/강사 전환 버튼, 예시 자료, 가짜 AI·저장은 만들지 않는다.

## 3. 메뉴

| 역할 | 메뉴 |
|---|---|
| 강사(teacher) | 내 커리큘럼 · 내 프로필 |
| 학과장·관리자(head·admin) | 강사 · 학과·과목 · 로드맵 · 방학 특강 · 준비물 · 특강·세미나 · 사이트 편집 |

학과장·관리자도 위 두 강사 메뉴를 쓸 수 있다(본인 강사 정보가 있을 때). 메뉴를 숨기는 것만으로 권한을 정하지 않는다. 모든 쓰기는 DB 정책·함수가 역할을 다시 확인한다.

## 4. 기존 자료 대응표

| 논리 자료 | 지금 DB | V4에서 |
|---|---|---|

| 프로필 | `instructors`(공개본), `instructor_profile_drafts`(제출본) | 그대로. 확정 = 제출본을 공개본에 넣고 공개 |
| 학과 | `departments`(이름·대표 이미지·소개·`former_names`) | 그대로 |
| 과목 | `subjects`(id 유지) | **`deleted_at` 추가**(과목 삭제 = 보관) |
| 학과 구성·순서 | `subject_departments`(순서 칸 없음, 순서는 `subjects.sort_order` 하나뿐) | **`subject_departments.sort_order` 추가**: 학과마다 따로 순서. 처음 값은 지금 순서로 채움 |
| 방학 특강 | `curriculum_sets.is_vacation`, `vacation_set_subjects` | 그대로 |
| 강사 커리큘럼 | `instructor_curricula`(단계 한 줄씩, `set_id`·`vacation`, `status` 대기/승인) | 그대로. **승인 = 검수 완료**로 본다(학과장이 승인한 기록이 근거) |
| 강사 준비물 | `instructor_subject_materials` | 그대로(원문 보존) |
| 공통 커리큘럼(일반) | `subject_weeks`(과목당 단계 줄) | 그대로 + 확정 기록 |

| 공통 준비물 | `course_prep_items`(과목·학과별) | 같은 원본을 커리큘럼·준비물 두 화면이 읽음. **`set_id` 추가**(방학 특강별) |
| 사이트 편집 | `main_media`, `loading_items`, `departments`, `menus`(`label` = 보이는 이름, `name` = 이동용) | 그대로 |
| 특강·신청자 | `seminars`(`is_listed`), `seminar_applications`(비공개) | 그대로. 신청 기능(`comsw_apply_seminar`)은 손대지 않음 |
| 공개 | `comsw_publish()` → `site_snapshots` 전체 다시 만들기 → `comsw_site_rows` | 아래 5장 |

## 5. 확정한 건만 공개하는 방법 (핵심)

지금 공개는 "실제 표 전체를 다시 묶어 스냅샷 한 장"이다. 그래서 실제 표에 확정 안 된 내용이 있으면 함께 공개된다.

V4 규칙:

1. **작성 중인 내용은 실제 표에 쓰지 않는다.**
   - 강사 커리큘럼: 지금처럼 `status='pending'` 줄(공개에 안 들어감).
   - 프로필: `instructor_profile_drafts`.
   - 공통 커리큘럼·공통 준비물·사이트 편집·특강: **새 표 `v4_drafts`**(대상 종류 + 대상 키 + 내용 json + 기준 버전 + 고친 사람·시각)에 저장. "저장"은 여기까지.
2. **확정 = DB 함수 한 번(한 트랜잭션)**: 그 건만 실제 표에 넣고 → 바로 `site_snapshots`에 새 스냅샷. 중간에 실패하면 둘 다 안 된다.
3. **다른 곳에서 반영 안 한 변경이 섞이지 않게 막기**: 확정 함수가 먼저 "지금 실제 표로 만든 공개 자료 = 마지막 스냅샷"인지 본다. 다르면(V3 등에서 고치고 '사이트에 반영'을 안 한 것이 있으면) 확정을 멈추고 알린다. 그래서 V3와 같이 쓰는 기간에도 남의 미확정 자료가 새지 않는다.
4. **동시 수정**: `v4_drafts`의 기준 버전(수정 시각)이 다르면 저장을 막고 다시 불러오게 한다. 확정 버튼은 누르는 동안 잠그고, 같은 확정을 두 번 해도 결과가 같게 만든다.
5. AI 실행·미리보기는 `v4_drafts`나 화면 안에서만 바뀐다. 공개되지 않는다.

확정 함수(모두 학과장·관리자만, 역할은 함수 안에서 다시 확인):

| 함수 | 넣는 곳 |
|---|---|
| `comsw_v4_confirm_instructor_curriculum(강사, 과목, 일반/특강)` | 그 대기 줄 → 승인(4단계 확인) |
| `comsw_v4_confirm_profile(강사)` | 제출본 → `instructors` |
| `comsw_v4_confirm_common(과목, 일반/특강)` | 4단계 문구·대표 이미지 → `subject_weeks`, 참고한 강사 자료 id·수정 시각 기록 |
| `comsw_v4_confirm_prep(과목, 일반/특강)` | 공통 준비물만 → `course_prep_items`(단계 문구는 안 건드림) |
| `comsw_v4_confirm_site(탭)` | 메인 / 학과 대표 / 로딩 / 하단 메뉴 중 그 탭만 |
| `comsw_v4_confirm_seminar(특강)` | 그 특강 정보만 |
| `comsw_v4_save_department_layout(학과)` | 학과 구성·순서 → 저장과 동시에 공개(구성은 바로 반영되는 일) |
| `comsw_v4_delete_subject` / `restore_subject` | 아래 6장 |

공개 자료 묶는 함수(`comsw_build_rows`)에서 바꿀 것: 삭제된 과목 빼기, 학과별 순서는 `subject_departments.sort_order`, 방학 특강 페이지는 그 특강의 공통 커리큘럼(없으면 지금처럼 일반 것). **공개 사이트 HTML은 바꾸지 않는 것이 목표**(시트 모양 유지).

## 6. 삭제·복원

| 행동 | 바뀌는 것 | 남는 것 |
|---|---|---|
| 학과에서 빼기 | 그 학과 연결·순서 한 줄 | 과목, 다른 학과, 모든 자료 |
| 방학 특강에서 빼기 | 그 특강 연결 한 줄 | 과목, 다른 특강·일반 자료 |
| 과목 삭제 | `deleted_at` 기록, 모든 학과·특강 연결 지움, 공개에서 빠짐 | 과목 id, 강사 원문, 검수본, 공통 문구·이미지·준비물 |
| 복원 | `deleted_at` 지움 | 자료 그대로. 학과·특강·순서·공개는 다시 연결해야 함 |

- 삭제 전에 영향받는 학과·방학 특강 목록을 보여 준다. 영구 삭제는 만들지 않는다.
- 지금 있는 "마지막 학과에서 빠지면 기타 과목으로" 트리거는 삭제된 과목에는 작동하지 않게 한다.
- 학과 삭제는 소속 강사가 있으면 막고 물어본다(규칙 미정, 9장).

## 7. 화면별 동작 (시안 배치 = 왼쪽 입력, 오른쪽 미리보기)

- **내 커리큘럼(강사)**: 내 학과(연결된 것만) → 수업할 과목 체크 → 일반 / 방학 특강 선택(특강이면 그 특강 과목만) → 과목마다 **1~4단계** 제목·내용·이미지 + 준비물 → [저장](대기 줄 갱신, 공개 안 됨) / [학과장에게 제출]. 단계·과목을 바꿔도 업로드는 시작한 칸에만 붙는다.
- **내 프로필(강사)**: 사진·경력·한마디 → 저장·제출(본인 것만).
- **강사**: 목록(홈페이지 노출 on/off = `is_listed`, 바로 공개) → 상세에서 프로필 / 커리큘럼 탭. 이번 제출만 보여 준다. [AI 사진 수정]·[AI 문장 다듬기]는 버튼으로만, 결과는 고칠 수 있는 초안 → [확정].
- **학과·과목**: 탭 학과 구성 / 전체 과목 / 삭제된 과목.
  - 과목 상세 한 화면에서: 쓰는 학과, 일반/방학 특강 고르기, 참고할 강사 체크(**검수 완료본만** 후보), [AI 공통 정리](체크한 강사 자료만 보냄), 단계마다 대표 이미지 1장 고르기(체크한 강사의 같은 단계 이미지만 후보), 공통 준비물 정리 → [확정].
  - 강사 체크를 풀어 고른 이미지의 출처가 사라지면 "다시 골라 주세요"로 확정을 막는다.
- **로드맵**: 모든 학과를 학과 구성 순서로 보여 줌. [순서 수정]은 그 학과의 학과 구성으로 바로 이동. 과목 문구는 지금 쓰는 `subjects.roadmap_summary`를 그대로 씀(복제·자동 AI 없음).
- **방학 특강**: 특강 만들기, 과목 구성(빼기 = 연결 해제), 그 특강 과목의 강사 자료·공통 자료는 학과·과목의 같은 편집기를 특강 기준으로 연다.
- **준비물**: 일반/특강 + 과목 → 공통 준비물 조회·수정·[확정](준비물만 공개).
- **특강·세미나**: 특강 여러 개 목록 → 고르면 정보 편집 + 신청 수강생 명단(로그인한 학과장·관리자만). [확정]으로 그 특강만 공개.
- **사이트 편집**: 탭 메인(여러 미디어 모두, 순서·문구) / 학과 대표(이미지·소개) / 로딩(여러 개 모두) / 하단 메뉴(보이는 이름·좌우·순서, 이동용 이름은 그대로). 탭마다 미리보기 + [확정].

## 8. 만드는 순서

| 단계 | 내용 | 운영 SQL |
|---|---|---|
| 1 | `admin-v4/` 틀, 로그인·세션·유휴 로그아웃, 역할별 메뉴, 시안 디자인. 모든 메뉴가 **실제 자료를 읽어서** 보여 줌(읽기만) | 없음 |
| 2 | 마이그레이션 하나(`v4_drafts`, `deleted_at`, 학과별 순서, 방학별 공통 칸, 확정 함수, 공개 묶음 수정). 로컬 테스트(pglite)로 "확정한 것만 공개" "다른 미반영 변경이 있으면 멈춤" 검증 | 사용자 실행 |
| 3 | 강사 두 메뉴 작성·제출, 강사 메뉴 검수·AI·확정 | — |
| 4 | 학과·과목(공통 정리·이미지·준비물·확정), 준비물, 로드맵, 삭제·복원 | — |
| 5 | 방학 특강, 특강·세미나, 사이트 편집 | — |
| 6 | 실제 계정으로 브라우저 확인(로그인·저장 후 새로고침·업로드·재생·삭제·복원·미검수 차단·해당 건만 공개), 전환 안내, Codex 검토 제안 | — |

각 단계 끝에 테스트를 돌리고, 배포는 "배포해"를 받은 뒤에만 한다. 운영 자료를 시험용으로 바꾸지 않는다.

## 9. 결정이 필요한 것 (실제 자료에서 나온 충돌)

1. **6단계 과목 5개**(공개 자료 기준): 아트 드로잉, 웹툰(1~6개월), 실내건축자격증, CG 포트폴리오, 모션 포트폴리오. 4단계 고정과 충돌함.
   - 안 A(추천): 공개된 6단계는 그대로 두고, V4에서 "4단계로 다시 정리 필요"로 표시. 학과장이 새로 4단계를 확정하면 그때 바뀜. 자동으로 자르거나 합치지 않음.
   - 안 B: 이 과목들만 예외로 6단계 허용.
2. **강사 커리큘럼 중 4단계가 아닌 것**: 운영 DB를 직접 읽을 수 없어 개수를 모름. 단계 2에서 확인용 SQL(읽기만)을 드리고, 결과를 보고 1번과 같은 방식으로 처리 제안.
3. **소속 강사가 있는 학과 삭제**: 규칙 미정 → 우선 막아 두고 실제로 필요할 때 정함.
4. **일반 / 방학 특강 공통 커리큘럼**: 지금은 과목당 한 벌. 기존 것은 "일반"으로 보고, 방학 특강은 비어 있으면 일반 것을 보여 줌(지금 공개 화면과 같음). 특강별로 확정하면 그때부터 따로 보임.

## 10. 확인 못 한 것

- 운영 DB의 비공개 자료(대기 중 제출 수, 강사 계정 연결 누락·중복, 프로필 제출본)는 연결 도구 권한이 없어 직접 보지 못했다. 단계 1 화면이 실제 로그인으로 읽어 보여 주므로 그때 확인한다.
